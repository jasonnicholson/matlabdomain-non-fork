Pages next to code¶

Tutorials, design notes and READMEs often sit next to the MATLAB code they describe. With matlab_src_page_suffixes, the extension indexes such .md and .rst files with the code, renders them into your documentation with mat:autopage, links between them and the code, generates a page for each with sphinx-matlab-apidoc and checks them with matlab-api-check. It is off by default.

Turning it on¶

List the suffixes in conf.py. Markdown needs myst-parser (the markdown extra, Installation) in extensions; without it, ".md" is a configuration error:

extensions = ["sphinxcontrib.matlab", "myst_parser"]
matlab_src_code_project_root = "../src"
matlab_src_page_suffixes = [".md", ".rst"]

Which files are pages¶

  • Files with one of the suffixes below the project root that matlab_src_include_patterns and matlab_src_exclusion_patterns select, like code. By default the exclusion patterns leave out README.*, CHANGES.*, CHANGELOG.*, LICENSE.*, CONTRIBUTING.*, CODE_OF_CONDUCT.* and SECURITY.* at the root, which describe the repository rather than the code. Add patterns for anything else, such as notes for tools ("**/CLAUDE.md").

  • Pages are read as UTF-8 (a byte-order mark is allowed), whatever matlab_src_encoding says. Invalid bytes are replaced, with a mat.encoding warning.

  • A page has a path reference (+demo/guide.md) but no MATLAB name, so guide.md next to guide.m is fine: names find the code.

The Sphinx source folder and the project root may be arranged three ways:

  • Apart (docs/ and src/): nothing to consider.

  • The source folder inside the root (root repo/, docs in repo/docs/): files in the source folder are documents, never pages. Code there is still indexed.

  • The root inside the source folder (docs/src/): Sphinx would read the pages as documents too. The extension adds each page to exclude_patterns when the configuration is read, so it does not. Adding or removing a page then changes exclude_patterns, and Sphinx reads every document again once.

The root cannot be the source folder itself (a configuration error), and on Windows a root on another drive than the source folder gets a mat.page warning: relative paths in pages cannot be resolved there.

Rendering a page¶

mat:autopage takes the page’s path reference and renders the page where it stands; a document of its own needs nothing else:

.. mat:autopage:: +demo/getting-started.md

The page’s headings become sections and its first heading is the document’s title. A page without a heading gets its file name as title, with a mat.page warning. :no-title: leaves out the first heading, so the rest continues the current section; sphinx-matlab-apidoc uses it for READMEs (below). This page renders +shapes/notes.rst from this documentation’s sample project:

.. mat:autopage:: +shapes/notes.rst

Notes on shapes¶

A reST page next to the code, in src/+shapes/. shapes.Circle is the simplest shape; its constructor starts like this:

classdef Circle < shapes.Shape
    % CIRCLE A circle with a radius.
    %

Every shape is a shapes.Shape.

Use mat:autopage in reST documents; in a Markdown document, a reST page would be read as Markdown.

Paths and links¶

Relative paths in a page are relative to the page’s folder, as on GitHub:

  • images (![plot](img/plot.png), .. image::, .. figure::) and downloads (:download:) are copied into the output;

  • literalinclude and include read files next to the page.

In Markdown, a relative link goes to:

  • another page: the document that renders it, with the page’s title when the link has no text ([](notes.rst)); an anchor (notes.rst#usage) goes to the section with that id, or with that slug when myst_heading_anchors is set;

  • a code file ([](scale.m), [the class](@Shape/Shape.m)): its API entry, with its MATLAB name when the link has no text;

  • any other file: a download;

  • anything else: myst-parser decides, as in any Markdown document.

The domain’s roles work in pages: :mat:func:`demo.scale` in reST, {mat:func}`demo.scale` in Markdown. :mat:page: links to a page by its path reference, with the page’s title as text: :mat:page:`+demo/getting-started.md`.

Raw HTML images (<img src="img/plot.png">) are rendered only with myst-parser’s html_image extension (myst_enable_extensions = ["html_image"]); other raw HTML is copied as is, and its relative paths are not resolved.

Pages with sphinx-matlab-apidoc¶

With matlab_src_page_suffixes in conf.py, sphinx-matlab-apidoc -c (Generating pages: sphinx-matlab-apidoc) writes a page for each page next to code, named after the file with its suffix after a - (getting-started.md -> getting-started-md.rst; a name that ends in .md.rst would lose its .md in a toctree). The folder’s page lists them in a “Pages” section after the API sections and before “Folders” (pages in @ folders on the page of the folder above, like their code). Pages come from conf.py only: no flag turns them on or off.

A folder’s README (README.md, readme.rst, any letter case) is not a page of its own: it is the introduction of the folder’s page, without its first heading. A README in an @ folder, which has no page, is an ordinary page.

The worked example has a Markdown page with an image in src/+demo/ and a reST page in src/utils/:

# Getting started with shapes

This tutorial sits next to the code it describes, in `src/+demo/`. It is a
Markdown page: `sphinx-matlab-apidoc` gives it a page of its own, and the
namespace's page lists it under "Pages".

![A square and a triangle](img/shapes.svg)

## Make a shape

Create a [`demo.Shape`](@Shape/Shape.m) and scale it with
{mat:meth}`demo.Shape.scale`:

```matlab
s = demo.Shape("square", 2);
s = s.scale(3);
```

## Measure

[](+geometry/distance.m) gives the distance between two points. The
[notes on the utilities](../utils/notes.rst) explain the helpers.

The generated namespace page starts with the README and lists the page:

.. Generated by sphinx-matlab-apidoc.

namespace demo
==============

.. mat:autofolder:: +demo/

.. contents::
   :local:
   :backlinks: none

.. mat:autopage:: +demo/README.md
   :no-title:

Classes
-------

demo.Shape
~~~~~~~~~~

.. mat:autoclass:: +demo/@Shape/Shape.m
   :members:
   :show-inheritance:

Pages
-----

.. toctree::
   :maxdepth: 4

   getting-started-md

Folders
-------

.. toctree::
   :maxdepth: 4

   +geometry/index

and the page’s own page holds one directive:

.. Generated by sphinx-matlab-apidoc.

.. mat:autopage:: +demo/getting-started.md

The templates get the pages as the keys pages and readme, and a page’s page comes from page.rst.jinja (sphinx-matlab-apidoc templates).

Checking pages¶

matlab-api-check (Checking help text: matlab-api-check) checks every page: the rule page-documented finds pages that no mat:autopage renders, or only in documents no toctree includes; page-links finds relative links and downloads to missing files and missing images. Exclude pages from the check with matlab_api_check_ignore_patterns.

Builds¶

A page is a dependency of the document that renders it, as are its images and included files: editing one reads only the documents that use it again. A missing image or link target is a dependency too, so its document is read on every build until the file exists (Sphinx does the same for missing images). Parallel builds (-j) give the same output as serial ones.
