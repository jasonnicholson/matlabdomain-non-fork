Documenting MATLAB code¶

The auto directives read a MATLAB file and write its documentation: the signature, the help text and, for classes, the members. This page shows them on a small sample project, rendered by this documentation’s own build. Directives, roles and indices lists every directive and option.

Auto and description directives¶

Every kind of object has two directives: an auto directive (mat:autofunction) and a description directive (mat:function).

mat:autofunction, mat:autoclass, …

mat:function, mat:class, …

Reads the source file

yes

never

Signature

from the file (or the one you give)

as you write it

Text

the help text, then your content

only your content

Members

with :members:

nested directives you write

No file has the name

a mat.not_found warning (“don’t know which object to document”); nothing is shown

no warning; shown as written

The auto directives write description directives, filled from the file. Use the auto directives for code that has files; write description directives for objects without a .m file, such as MEX functions (below).

The sample project¶

conf.py of these docs sets matlab_src_code_project_root = "src", the folder with:

src/
    times_two.m              a function
    times_two_napoleon.m     a function with Google-style help
    +shapes/                 namespace shapes
        Shape.m              class shapes.Shape
        Circle.m             class shapes.Circle (a subclass of Shape)
        Color.m              enumeration shapes.Color
        totalArea.m          function shapes.totalArea
        @Polygon/            class folder: class shapes.Polygon
            Polygon.m
            perimeter.m      a method in its own file
        private/
            checkPositive.m  a private function
    scripts/
        shapes_demo.m        a script
    apps/
        ShapesApp.mlapp      an App Designer app

Naming what to document¶

The argument of an auto directive names one file or member, in one of these ways:

  • its MATLAB name, as you would type it in MATLAB: shapes.Circle, shapes.Circle.area, times_two;

  • its path reference, the path below the project root: +shapes/Circle.m, +shapes/Circle.m.area, +shapes/@Polygon/Polygon.m;

  • a path or name relative to the current folder (below).

A MATLAB name must belong to exactly one file. When several files share it (two folders with a utils.m, say), the directive warns (mat.ambiguous) and lists their path references; use one of those. Names, references and links explains names and references in detail.

Functions¶

.. mat:autofunction:: shapes.totalArea
shapes.totalArea(shapeList, opts)¶

TOTALAREA Sum of the areas of several shapes.

total = shapes.totalArea(shapeList) adds the areas. total = shapes.totalArea(shapeList, Scale=s) multiplies the sum by s.

The comments in the arguments blocks describe the inputs and the output. matlab-api-check counts them; the documentation does not show them, like MATLAB’s help.

See also shapes.Circle

The signature lists the input names. Name-value arguments (opts.Scale in an arguments block) appear as their structure, opts.

Classes¶

mat:autoclass documents the class help; :members: adds its constructor, properties, enumeration values and methods, in sections:

.. mat:autoclass:: shapes.Circle
   :members:
   :show-inheritance:
class shapes.Circle¶

Bases: shapes.Shape

CIRCLE A circle with a radius.

c = shapes.Circle(2) creates a circle of radius 2.

See also shapes.Shape, shapes.totalArea()

Constructor Summary
Circle(radius)¶

CIRCLE Create a circle.

Inputs:

radius - The radius, a positive number

Property Summary
Radius (1,1) double {mustBePositive} = 1¶

Radius, in meters

Method Summary
area()¶

AREA Area of the circle.

Outputs:

a - pi times the radius squared

static unit()¶

UNIT A circle of radius 1.

Outputs:

c - The circle

  • :show-inheritance: adds the “Bases:” line, with links to base classes that are documented. MATLAB’s own classes (handle, matlab.mixin.Copyable) are not documented in your project; they are shown as text, without a “reference target not found” warning (see matlab_external_names for the names and how to add others).

  • Members without help are left out (enumeration values are always shown); :undoc-members: adds them.

  • Members with Access = private or protected, Hidden members and members whose access is a list of classes (Access = ?OtherClass) are left out. :private-members:, :protected-members:, :hidden-members: and :access-list-members: add them: all of them, or the ones you name (for :access-list-members:, the classes that have access). Circle above has a hidden property Tag and a private method check.

  • :members: area, Radius documents only the named members; :exclude-members: unit leaves out the named ones.

  • The signatures show the attributes a reader needs: abstract and sealed classes and methods, static methods, abstract, constant, dependent and read-only properties (read-only: SetAccess is stricter than the read access, as with SetAccess = immutable), and the constructor arguments of enumeration values (Red (1, 0, 0); matlab_show_property_default_value turns them off with the property defaults).

  • Abstract methods (declared without a body) are documented; their help is found as for properties: a comment on the line, or a comment block right above or below it. get./set. property methods and converter methods with dotted names are not documented. MATLAB does not list property methods either (methods, metaclass): describe what they do (a computed value, a check on assignment) in the property’s help, which help Circle.Radius shows.

  • Events are listed under “Event Summary”, with their help found as for properties. ListenAccess decides who sees them, as Access does for methods (ListenAccess = protected needs :protected-members:); link to one with :mat:event:.

Enumeration values, here in the order of the file (:member-order: bysource; the default is alphabetical):

   :members:

A class folder (@Polygon/) is documented through its class. Methods defined in their own files in the folder (perimeter.m) are members like the methods in the class file. A method whose signature the classdef declares in a methods block (methods (Static) with out = make(x)) has that block’s attributes, so it is static, private, protected or hidden as declared; a method file without a declaration is public:

.. mat:autoclass:: shapes.Polygon
   :members:
   :show-inheritance:

Bases: shapes.Shape

p = shapes.Polygon([0 1 0], [0 0 1]) creates a triangle. The method perimeter is defined in its own file, @Polygon/perimeter.m.

A folder @X/ is a class folder only if @X/X.m is a classdef. Old-style classes (a class folder without a classdef, from before MATLAB R2008a) are not supported: their files are functions. Document each file with mat:autofunction.

Single members¶

mat:automethod and mat:autoattribute (properties) document one member. The basic class help with its members, and one method again (with :noindex:, because area is already documented above):

.. mat:autoclass:: shapes.Shape
   :members:
   :show-inheritance:

.. mat:automethod:: shapes.Circle.area
   :noindex:

Bases: handle

Every shape has a name and a fill color, and can describe itself.

Shape Properties:

  • Color - Fill color

shapes.Circle.area()

The help text of Shape lists its properties and methods in MATLAB’s Shape Properties: / Shape Methods: form. With matlab_auto_link = "basic", as in these docs, those entries and the “See also” line become links (Help text).

mat:autoenum is mat:autoattribute for an enumeration value, and mat:autoevent documents one event.

Scripts, apps and private files¶

.. mat:autofunction:: +shapes/private/checkPositive.m

.. mat:autoscript:: scripts/shapes_demo.m

.. mat:autoapplication:: apps/ShapesApp.mlapp
checkPositive(value)¶

CHECKPOSITIVE Error unless VALUE is positive (a private helper).

Inputs:

value - The number to check

shapes_demo¶

SHAPES_DEMO Create two shapes and print their total area.

Run it from the folder that contains +shapes.

ShapesApp¶

Summary of app

Description of app

Files in private/ folders are documented like any other file. Their MATLAB name (checkPositive) is only visible from the parent folder, as in MATLAB, so from elsewhere name them by path. The private/ folder of a class folder (@Polygon/private/) holds scripts, functions and classes that only that class can use; they are files, not members of the class. App Designer apps show the summary and description stored in the app.

mat:autodata documents a script as data (a script that defines variables, such as a parameter file): it looks the same, but its object type is data (role :mat:data:) and it gets an index entry.

Folders and the current folder¶

mat:autofolder documents a folder. A + folder is shown as a namespace; any other folder as folder and its path:

.. mat:autofolder:: +shapes/
   :synopsis: Shapes, their colors and areas
namespace shapes¶

The folder also becomes the current folder of the page: for the rest of the page, or until the next folder directive, names are looked up relative to it, so Circle.m, shapes.Circle and the private checkPositive all work. To set the current folder without documenting the folder, use mat:currentfolder:

.. mat:currentfolder:: +shapes/

. is the project root and None clears the current folder.

:members: on mat:autofolder documents the files directly in the folder: functions, classes, scripts and apps, in alphabetical order. It does not include class folders (@X/), private/ or subfolders, and leaves out Contents.m and the other special files (Help text). The options apply to the members too: :members: on a folder also documents every member of its classes. For a whole project, scmd apidoc writes one directive per file instead (Generating pages: scmd apidoc).

Adding text¶

Content below an auto directive is added after the help text:

.. mat:autofunction:: shapes.totalArea

   Added by hand: an example that is not in the help text.

Writing directives by hand¶

The mat:function, mat:class, mat:method, mat:staticmethod, mat:attribute, mat:event, mat:script, mat:application, mat:data and mat:folder directives describe an object without reading a file, for example a MEX function:

.. mat:function:: fastSolve(A, b)
   :annotation: (MEX file)

   Solve ``A*x = b`` with a compiled solver.

   :param A: A square matrix.
   :param b: The right-hand side.
   :returns: The solution ``x``.
fastSolve(A, b) (MEX file)¶

Solve A*x = b with a compiled solver.

Parameters:

  • A – A square matrix.

  • b – The right-hand side.

Returns:

The solution x.

If the name matches a file below the project root, the object gets that file’s path reference, so links to the file land here; the file itself is not read. Otherwise its reference is the name as written, below the current folder if one is set (here +shapes/fastSolve). Either way there is no warning. Nest mat:method and mat:attribute in mat:class to document members. The auto directives generate these directives; you rarely need them for code that has files.
