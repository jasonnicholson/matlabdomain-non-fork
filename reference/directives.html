Directives, roles and indices¶

Every directive and role is in the mat domain. With primary_domain = "mat" the mat: prefix may be left out. Documenting MATLAB code and Names, references and links show them in use.

Auto directives¶

An auto directive takes one argument: a MATLAB name, a path reference, or a name relative to the current folder (Names, references and links), optionally followed by a signature, (a, b), that replaces the one read from the file. It reads the file and writes the matching description directive (below) with the help text. Content below the directive is added after the help text. autodoc_default_options supplies default options. If no object matches the argument, the build warns (mat.not_found, “don’t know which object to document”) and the directive writes nothing.

.. mat:autofunction:: name¶

A function file. The signature lists the inputs; with autodoc_docstring_signature, a first help line that looks like the signature replaces it.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autoclass:: name¶

A class: a classdef file, or the class of a class folder (@Cls/Cls.m, with the methods in other files of the folder). With :members:, its members follow in the sections “Constructor Summary”, “Property Summary”, “Enumeration Values” and “Method Summary”.

:members: (no value, or a comma-separated list of member names)¶

Document all members, or the named ones.

:undoc-members:¶

Also document members without help (enumeration values are always documented).

:private-members: (no value, or a comma-separated list of member names)¶

Also document members with Access = private (all, or the named ones).

:protected-members: (no value, or a comma-separated list of member names)¶

Also document members with Access = protected.

:hidden-members: (no value, or a comma-separated list of member names)¶

Also document Hidden members.

:access-list-members: (no value, or a comma-separated list of class names)¶

Also document members whose access is a list of classes (Access = ?OtherClass or {?A, ?B}): all, or those accessible to the named classes (with or without ?).

:friend-members:¶

The old name of :access-list-members:.

:exclude-members: (a comma-separated list of member names)¶

Leave out the named members.

:member-order: (``alphabetical``, ``groupwise`` or ``bysource``)¶

The order of the members in each section; default autodoc_member_order.

:show-inheritance:¶

Add a “Bases:” line with the superclasses.

:noindex:¶
:no-index:¶

Do not create link targets or index entries, also for the members.

.. mat:automethod:: name¶

One method: Cls.method (a MATLAB name or a path reference such as +pkg/Cls.m.method), or the method name alone inside a class. Static methods are written as mat:staticmethod. In the signature, a first input named obj or self is left out, except for the constructor and static methods (they have no object).

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autoattribute:: name¶

One property or enumeration value, named like a method.

:annotation: (no value, or text)¶

Without a value, show neither default value nor specification. With a value, show = <value> after the name instead.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autoenum:: name¶

The same as mat:autoattribute, for an enumeration value; it takes the same options.

:annotation:¶
:noindex:¶
:no-index:¶

As for mat:autoattribute.

.. mat:autoevent:: name¶

One event of a class, named like a method.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autoscript:: name¶

A script file.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autodata:: name¶

A script documented as data (mat:data), for example a file of parameters.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autoapplication:: name¶

An App Designer app (.mlapp), with the summary and description stored in the app.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:autofolder:: name¶

A folder (path reference ending with /, or a namespace’s MATLAB name), written as mat:folder. It also sets the current folder. The options apply to the members too, so :members: also documents the members of the folder’s classes.

:members: (no value, or a comma-separated list of file names)¶

Document the functions, classes, scripts and apps directly in the folder (not class folders, private/ or subfolders; not Contents.m and the other special files), sorted by name; or the named ones.

:undoc-members:¶
:private-members:¶
:protected-members:¶
:hidden-members:¶
:access-list-members:¶
:friend-members:¶
:exclude-members:¶
:member-order:¶
:show-inheritance:¶

As for mat:autoclass; they apply to the folder’s members and their members.

:synopsis:¶
:platform:¶
:deprecated:¶

As for mat:folder.

:noindex:¶
:no-index:¶

Do not create link targets or index entries.

Sidecar docs¶

.. mat:autosidecar:: reference¶

Render a sidecar doc (Sidecar docs): the path reference of a .md or .rst file that matlab_src_sidecar_suffixes indexes. Its headings become sections; the first is the sidecar doc’s title. One without a heading gets its file name as title, with a mat.sidecar warning. Relative paths in it are relative to its folder. A reference that is not an indexed sidecar doc writes nothing, with a mat.sidecar warning. Use it in reST documents (in a Markdown document, a reST sidecar doc would be read as Markdown).

:no-title:¶

Leave out the sidecar doc’s first heading: the rest of it continues the current section (a folder’s README as the introduction of the folder’s page).

Description directives¶

The auto directives write these; write them by hand for objects without a source file (Documenting MATLAB code). They never read a file and never warn about a missing one: they show the signature and content as written. The argument is a signature: a name, optionally followed by (arguments) (optional arguments in [...]) and -> annotation. If the name matches a source file, the object gets its path reference (for links), not its help. Their content may use Sphinx’s info fields: :param x:, :type x:, :returns:, :rtype:, :raises Cls: (a link to an error class), :var v:. A type in :type x: or :vartype v: links to a documented object of that name; any other type (double, (1,1) string) is shown as text, without a “reference target not found” warning.

.. mat:function:: signature¶

A function.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

:annotation: (text)¶

Text after the signature.

:reference: (a path reference)¶

The object’s path reference (the auto directives set it).

.. mat:class:: signature¶

A class (shown as class <name>). Methods and properties described in its content belong to it.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

:abstract:¶
:sealed:¶

Show the MATLAB class attribute before class (abstract class Shape). mat:autoclass sets them from the classdef.

.. mat:method:: signature¶

A method, inside mat:class or named Cls.method.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

:abstract:¶
:sealed:¶

Show the MATLAB method attribute before the name (abstract area()). The auto directives set them from the methods block.

.. mat:staticmethod:: signature¶

A static method, shown with static.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶
:abstract:¶
:sealed:¶

As for mat:method.

.. mat:attribute:: name¶

A property or enumeration value.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

:abstract:¶
:constant:¶
:dependent:¶
:read-only:¶

Show the property attribute before the name (constant Max = 10). The auto directives set them from the properties block; read-only when SetAccess (or Access) is stricter than the read access (SetAccess = private, immutable, …), except for constants.

.. mat:event:: name¶

An event, inside mat:class or named Cls.event.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

.. mat:script:: name¶

A script.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

.. mat:application:: name¶

An App Designer app.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

.. mat:data:: name¶

Data, such as a script that defines variables.

:noindex:¶
:no-index:¶
:annotation:¶
:reference:¶

As for mat:function.

.. mat:folder:: name¶

A folder: a path reference (with or without the trailing /) or a namespace’s MATLAB name. A valid + folder is shown as namespace <MATLAB name>, any other as folder <path>; an @ class folder is an error (document its class). Sets the current folder. A folder may be described on several pages; the last one is the link target.

:synopsis: (text)¶

A one-line description, shown in the folder index and link titles.

:platform: (text)¶

Platforms, shown in the folder index.

:deprecated:¶

Mark the folder as deprecated in the folder index.

:noindex:¶
:no-index:¶

Do not create a link target or an index entry.

.. mat:currentfolder:: name¶

Set the current folder for the rest of the page without documenting it: a folder path or namespace name, . for the project root, or None to clear it.

Roles¶

The target is a MATLAB name, a path reference or a name relative to the current folder. ~target shows only the last part; title <target> sets the text; a leading . also matches the end of MATLAB names. A role prefers objects of its type, then accepts any.

:mat:func:¶

A function. () is added to the text (add_function_parentheses).

:mat:class:¶

A class.

:mat:meth:¶

A method or static method. () is added to the text.

:mat:attr:¶

A property or enumeration value.

:mat:event:¶

An event.

:mat:folder:¶

A folder or namespace.

:mat:scpt:¶

A script.

:mat:app:¶

An App Designer app.

:mat:data:¶

An object documented with mat:data.

:mat:obj:¶

An object of any type.

:mat:const:¶

An object of any type (no object type uses it).

:mat:enum:¶

An object of any type (enumeration values are attributes; prefer mat:attr).

:mat:sidecar:¶

A sidecar doc, by its path reference only (:mat:sidecar:`+demo/guide.md`): a link to the document that renders it, with its title (its first heading) as text unless one is given.

Indices¶

The domain adds the MATLAB Folder Index, which lists the documented folders: link to it with :ref:`mat-folderindex` (MATLAB Folder Index). The general index (genindex) has an entry for every documented object.
