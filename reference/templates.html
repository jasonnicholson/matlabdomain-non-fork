scmd apidoc templates¶

scmd apidoc renders Jinja templates, which matlab_apidoc_templatedir can replace (Generating pages: scmd apidoc). The defaults are in sphinxcontrib/matlab_apidoc/templates/. They are rendered with Sphinx’s ReSTRenderer, which adds the filters e (escape reST) and heading (underline a title; heading(2) for the second level).

The variables below are a public interface: new ones may be added in any release, but renaming or removing one is a breaking change. Every generated file starts with the marker line .. Generated by scmd apidoc., which the command adds outside the templates.

namespace.rst.jinja¶

In namespace grouping, one page of a namespace or of the global namespace.

docname

The page, relative to the output folder, without suffix (demo, demo-2, global).

title

namespace demo or Global; with several pages, followed by the range of entries (namespace demo (101-200)).

namespace

The namespace’s MATLAB name, or None for the global namespace.

kind

"namespace" or "global".

page, pages

The number of this page and of the namespace’s pages (1 and 1 for most).

first, last

The numbers of the first and last entries on this page, counting from 1 across the namespace’s pages.

sections

(title, entries) pairs in the order Functions, Classes, Scripts, Apps; only sections with entries on this page. entries are described below.

sidecars

The sidecar docs on this page, sorted by file name; each a dictionary with ref (the path reference), name (the file name) and docname (None). They come after the files, so they are on the last pages.

separate

True with matlab_apidoc_separate.

maxdepth

The :maxdepth: of the toctrees (matlab_apidoc_maxdepth).

root.rst.jinja¶

The root page, in both groupings.

docname

The toc file (matlab_apidoc_tocfile).

title

"API reference".

pages

The docnames of the other pages, each group with all its pages. In namespace grouping: Global first, then the namespaces sorted by name, ignoring case. In folder grouping: the root folder’s page first, then the folders sorted by path, ignoring case.

maxdepth

The :maxdepth: of its toctree.

folder.rst.jinja¶

In folder grouping, one page of a folder with files or sidecar docs.

docname

The page, relative to the output folder, without suffix (+demo/index, +demo/index-2; root for the root folder).

ref

The folder’s path reference (+demo/; ./ for the root).

title

folder and the folder’s path reference: folder +demo/, folder utils/, or folder ./; with several pages, followed by the range of entries (folder utils/ (101-200)).

kind

"namespace", "folder" or "root".

is_root

True for the root folder’s page.

page, pages

The number of this page and of the folder’s pages (1 and 1 for most). The default template documents the folder (mat:autofolder) on page 1 only.

first, last

The numbers of the first and last entries on this page, counting from 1 across the folder’s pages.

sections

(title, entries) pairs in the order Classes, Functions, Scripts, Apps; only sections with entries on this page. entries are described below.

separate

True with matlab_apidoc_separate.

maxdepth

The :maxdepth: of the toctrees (matlab_apidoc_maxdepth).

sidecars

The sidecar docs on this page (the folder’s own, and those in its @ folders), sorted by file name; each a dictionary with ref (the path reference), name (the file name) and docname (its own page, relative to this page). They come after the files, so they are on the last pages. Empty when sidecar docs are off.

readme

The path reference of the folder’s README (any letter case, any page suffix), the introduction of its first page, or None.

Entries¶

Each entry describes one file, or one block of a Simulink library (both groupings):

ref

The path reference of the file or block (lib.slx/Group/Gain).

kind

"class", "function", "script", "application", "model", "library", "subsystem" (a subsystem file) or "library_block".

directive

The auto directive, such as "mat:autoclass".

argument

The directive’s argument: ref, with each line break of a block name followed by the indentation that continues it.

options

A dictionary of directive options; {"members": "", "undoc-members": "", "show-inheritance": ""} for classes, else empty.

title

The heading: the MATLAB name, or the path reference if MATLAB cannot call the file (or, on a namespace page, if another file of the page has the same MATLAB name).

display

The name signatures show (the same as title).

matlab_name

The MATLAB name, or None if MATLAB cannot call the file. A library block’s is the library’s MATLAB name and its block path.

callable

matlab_name is not None.

private

True for files below private/.

docname

With matlab_apidoc_separate: the file’s page, relative to the folder page (on a namespace page: relative to the output folder). Otherwise None.

object.rst.jinja¶

With matlab_apidoc_separate, one page per file. It gets the variables of one entry, with docname relative to the output folder.

sidecar.rst.jinja¶

In folder grouping, one page per sidecar doc (guide.md -> guide-md.rst), with or without matlab_apidoc_separate. Its title is the sidecar doc’s first heading. Variables: ref, name and docname (relative to the output folder), as in sidecars above.
