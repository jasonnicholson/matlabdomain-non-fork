Release notes¶

1.0.0 (Unreleased)¶

The first stable release; from here on the project follows semantic versioning. It breaks with 0.x in many places: see “Migrating from 0.22 and earlier” in the documentation.

  • Consolidate build, test and static-analysis policy in pyproject.toml; document repository configuration and check its inventory. Add a shared Ruff/basic-Pyright gate and portable editor settings without changing the supported test matrix or manual-only CI triggers.

  • The documentation is rewritten: getting started, a user guide, a reference of every configuration value, directive, role, option and warning, and a developer guide. Examples are rendered by the documentation’s own build.

  • Drop support for Python <=3.10.

  • Drop support for Sphinx <=7.x.

  • Breaking: the mat:classmethod directive is removed. MATLAB has no class methods apart from static methods; use mat:staticmethod. No auto directive wrote it, so only hand-written pages change.

  • Breaking: a method in its own file of a class folder takes the attributes of its signature in the classdef (methods (Static) with out = make(x)): it is documented as mat:staticmethod when static, mat:autoclass leaves it out when it is private, protected, access-listed or hidden (unless an option adds it), and matlab-api-check checks it only when it is public, counting the first input of a static method. They were all public, non-static methods before, so a page that links to such a method needs the option that documents it (:private-members:, …), and a static one is in the inventory as mat:staticmethod.

  • Breaking: the signature of a static method keeps a first input named obj or self (static make(obj, y)): a static method has no object, so that input is a real one. Other methods still leave it out.

  • matlab-api-check does not check a Hidden class or its members (it counts the class as hidden in the report), as for Hidden members.

  • Signatures show MATLAB attributes: abstract and sealed classes and methods; abstract, constant, dependent and read-only properties (SetAccess stricter than the read access). New flag options of mat:class, mat:method, mat:staticmethod and mat:attribute (:abstract:, :sealed:, :constant:, :dependent:, :read-only:); the auto directives set them.

  • Abstract methods (declared without a body) are documented, marked abstract, with their help found as for properties. matlab-api-check does not check them: MATLAB’s help shows no text for them.

  • Enumeration values show their constructor arguments (Red (1, 0, 0)) when matlab_show_property_default_value is true.

  • Events are documented: an “Event Summary” section in mat:autoclass, mat:autoevent, the mat:event directive and the :mat:event: role (inventory type mat:event). ListenAccess and Hidden filter them as Access and Hidden filter methods. New matlab-api-check rule event-description (a warning by default); reports count events (event).

  • A property or event whose read access (GetAccess, ListenAccess) is a list of classes is left out of mat:autoclass unless :access-list-members: adds it, as with Access lists; it was shown.

  • Attributes written ~Hidden (Hidden = false) no longer make a class fail to parse (it was documented without content), and logical values written as numbers or with ~ (Hidden = 0, Static = ~true) are read as MATLAB reads them; they were read as true.

  • An unknown matlab_* name is a ConfigError also when another extension sets it while the configuration is read (for example sphinx-multiproject’s config option), not only in conf.py.

  • The documentation describes several projects, several versions (sphinx-multiversion), sphinx-multiproject and one search over several sites, with what was checked.

  • Breaking: matlab_show_property_default_value and matlab_show_property_specs default to True: properties show their default value, size, class and validators. Set them to False for the old output.

  • Breaking: matlab_add_namespace_names (default True) replaces Sphinx’s add_module_names for MATLAB signatures; the MATLAB domain no longer reads add_module_names.

  • An auto directive that matches no object warns with the subtype mat.not_found and the page and line of the directive; its “matches several objects” warning gives the location too.

  • Types in :type x: and :vartype v: fields (as written by sphinx.ext.napoleon) link to documented objects and are plain text otherwise; with nitpicky they no longer warn “reference target not found” (MATLAB types such as double are never documented).

  • Use treesitter for parsing.

  • Added new configuration: matlab_version (default "R2026a", oldest supported "R2024a"). It selects version-dependent MATLAB naming rules. Scripts and functions in a subfolder of a class folder (@C/sub/x.m) are callable before R2026a only.

  • Added new configuration: matlab_namelengthmax (63 or 2048). The default None derives it from matlab_version (2048 from R2025a on). An explicit value always wins over the derived default.

  • Breaking: objects are identified by path reference, the path relative to the project root with its extension (target/+package/ClassBar.m, members target/+package/ClassBar.m.myMethod, folders target/+package/). Signatures and the inventory’s display names show the MATLAB name (package.ClassBar), formed like MATLAB does (form_matlab_name). Cross-references resolve an exact path reference, then relative to the current folder (including its private/), then a unique MATLAB name; an ambiguous name warns and lists the matching references. There is no found-first precedence.

    • Anchors are mat- followed by the escaped path reference (#mat-target/+package/ClassBar.m); inventory names are path references. Legacy dotted anchors, module- anchors and aliases are gone, so existing deep links and intersphinx references change.

    • mat:module, mat:automodule, mat:currentmodule and :mat:mod: are replaced by mat:folder, mat:autofolder, mat:currentfolder and :mat:folder:. A valid + folder shows namespace <name>, any other folder folder <path>; @Class folders are documented through their class. The module index is now the folder index (mat-folderindex.html).

    • New configuration matlab_src_code_project_root (relative to the Sphinx source directory). matlab_src_dir was removed: setting it raises a ConfigError.

    • Setting matlab_keep_package_prefix or matlab_short_links raises a ConfigError; MATLAB names are always displayed. One error names every removed value set in conf.py.

    • Files MATLAB cannot call for matlab_version (keyword namespaces, invalid names, @C/sub files from R2026a, …) are documented by path with one mat.not_callable warning each (suppress_warnings) that says why; files below private/ never warn.

  • References to another project’s MATLAB objects (sphinx.ext.intersphinx) resolve by MATLAB name too (:mat:class:`geom.Circle`), not only by path reference: in any inventory, or in the one named with lib: or :external+lib:. A MATLAB name that several objects have, or a path reference that several inventories have, warns with mat.ambiguous and stays unlinked. The new user-guide page “Linking between projects” gives the setup and explains which links follow an object that page splitting moves to another page.

  • HTML builds write a stable address for every documented object, mat/name/<MATLAB name>.html (a list of the objects when several have the name) and mat/ref/<path reference>.html, which redirect to the page the object is on; the “¶” link of an object and its entry in objects.inv point to it, so other projects’ links survive page splitting even with an old inventory. A copied page address that no longer has the object, or a page that is gone (404.html), opens the object’s stable address. New matlab_stable_urls (default True) turns it off.

  • Incremental HTML builds remove the pages whose sphinx-matlab-apidoc source is gone, and write again every page with a link to a MATLAB object when objects were added, removed or moved to other pages.

  • Requires tree-sitter-matlab 1.3.2 (was 1.3.0 to 1.3.1).

  • Fixed a segmentation fault (exit code 139) with tree-sitter 0.26.0 on standard CPython builds. Its Point.row getter corrupts reference counts, so point rows are now read by index.

  • Breaking: docstrings follow MATLAB help (R2026a). A comment block before a file’s function or classdef line wins over the block after it, so licence and copyright headers become the docstring. Blank lines between a declaration and its block are allowed. Methods keep using the block after their function line. Files with CRLF line endings keep all lines of a block. Like MATLAB help, the text is the first run of % lines, so a %{ ... %} block comment gives {.

  • .m files are classified by their first line of code (whole-word function/classdef, classify()); a script with local functions is now a script, not a function. New suppressible warnings: mat.invalid_matlab when that type and the tree-sitter parse disagree (likely invalid MATLAB), and mat.empty_code_file for empty files, which are documented as scripts. A help file (comments only) does not warn: it is documented as a script, or as a function when a MEX file of the same name is next to it (MATLAB runs the MEX file and shows the help of the .m file).

  • Contents.m, slblocks.m, sl_customization.m, pathdef.m, matlabrc.m and rtwmakecfg.m are left out of mat:autofolder members and never warn; an explicit directive still documents them.

  • Source files are found through a file-type handler registry (.m, .mlapp), the extension point for Simulink and Simscape files.

  • Parsing is faster: tree-sitter queries are compiled once and the tree-sitter version is no longer looked up per file.

  • One bad source file no longer stops the build. A file that cannot be read or parsed (permissions, a corrupt .mlapp, a parser error) gets one suppressible mat.parse_error warning (with the line of the first syntax error when tree-sitter finds one) and is documented without content; references to it still resolve. An unreadable folder or a file name that is not valid UTF-8 warns the same way.

  • A function with a dotted name (function y = vlt.plot.hist2d(...)) no longer crashes the build: it is documented under its file name, as MATLAB names it, with a mat.invalid_matlab warning. arguments blocks with ~ entries no longer crash, and classes with ... between classdef, the attributes, the name and the superclasses keep their superclasses, docstring and members.

  • Breaking: matlab_src_encoding is applied (it was ignored). A byte-order mark selects UTF-8/16/32; otherwise the configured codec, or by default UTF-8, where a file that is not valid UTF-8 uses the Windows ANSI code page on Windows or ISO-8859-1 elsewhere, like MATLAB R2026a, with a suppressible mat.encoding warning (it used to show backslash escapes). An unknown or non-text codec is a ConfigError. Cached environments from earlier versions are rebuilt.

  • Large projects build fast: each build indexes the source files (reads and classifies each file once) and parses a file with tree-sitter only when a page needs it. Parses are cached by path, modification time and size; only pages that used a changed file are read again (when files are added, removed or change type, every page that looks up sources). Parallel builds (-j) are supported. New matlab_src_cache_text (default True) keeps the text read by the index for the parse during a build.

  • New configuration matlab_src_include_patterns (default ["**/*"]; [] selects no files) and matlab_src_exclusion_patterns (default the root files README.*, CHANGES.*, CHANGELOG.*, LICENSE.*, CONTRIBUTING.*, CODE_OF_CONDUCT.* and SECURITY.*): globs relative to matlab_src_code_project_root, matched like exclude_patterns, case-sensitive. Patterns must stay below the root (ConfigError otherwise) and need matlab_src_code_project_root. A link below the root that leaves it is skipped with a mat.outside_root warning.

  • Breaking: mat.invalid_matlab and parse failures (mat.parse_error) are reported for the files that pages read in the build use, once per build; a file no page uses is not parsed. Index warnings (mat.encoding, mat.empty_code_file, mat.not_callable, unreadable files and folders) still appear on every build.

  • New command sphinx-matlab-apidoc (also python -m sphinxcontrib.matlab_apidoc): writes reST pages with mat:auto* directives for the MATLAB files of a project, from Jinja templates that can be replaced (matlab_apidoc_templatedir). By default (matlab_apidoc_group = "namespace") it writes one page per namespace, merging all its folders, and Global for the files outside any namespace, listed flat on the root page (Global first); sections Functions, Classes, Scripts, Apps and the sidecar docs; at most matlab_apidoc_page_size entries (default 100) per page; private/ files are left out (matlab_apidoc_private = True lists them with the folder above). matlab_apidoc_group = "folder" writes one page per folder with files, titled by path (folder a/+ns/), also listed flat on the root page (the root folder’s page first, named root). Its template context is a public interface: renaming or removing a key is a breaking change. See examples/apidoc. sphinx-matlab-apidoc -c DIR (default: the current folder) reads every setting from DIR/conf.py: the source settings of the build and the new matlab_apidoc_* values (output folder, grouping, page size, one page per file, toctree depth, root page, suffix, templates, removal of stale pages). Its flags only control a run: -f, -n, --check, -q. Generated pages (those that start with its marker line) are rewritten when they change and removed when they are no longer pages; --check exits with 1 when the pages are out of date. A page that differs only in line endings (a Windows checkout with core.autocrlf) is unchanged. Its summary line starts with Check: under --check and Dry run: under -n. For full control, a script calls the Python API (IndexSettings, build_index, generate, ApidocOptions). The command does not run inside sphinx-build; run it before the build. It prints its warnings like the build and skips those named in suppress_warnings.

  • Breaking: a matlab_* name in conf.py that is not a configuration value (a typo, a value this version does not have, a helper variable) is a ConfigError in the build and in sphinx-matlab-apidoc, with the closest value as a suggestion; Sphinx ignores such names silently. sphinx-matlab-apidoc also rejects abbreviated options.

  • The function files of a class folder @X/ are methods only if X.m is a classdef. In any other @ folder (an old-style class, a classdef named differently, no class file) they are documented as functions; before, the folder’s only classdef took them as methods, whatever its name. Cached environments from earlier versions are rebuilt.

  • A script’s docstring is its first comment block. It used to be one of its top-level comment blocks, chosen by an unordered query result: often a later block (a live script’s %[appendix]), and not always the same one from build to build. Cached environments from earlier versions are rebuilt.

  • sphinxcontrib is a native (PEP 420) namespace package, like in the other sphinxcontrib-* packages: sphinxcontrib/__init__.py is no longer shipped. It imported pkg_resources, so without setuptools the package, and Sphinx’s own sphinxcontrib extensions, failed to import.

  • Breaking: Python-domain features that do not apply to MATLAB are removed: the mat:decorator, mat:decoratormethod, mat:exception and mat:autoexception directives, the :mat:exc: role, and the :special-members: and :inherited-members: options of mat:autoclass (:inherited-members: crashed the build). Names in :raises: fields link to classes.

  • sphinxcontrib.matlab sets up sphinx.ext.autodoc itself; the mat:auto* directives failed when it was not in extensions. An invalid option of a mat:auto* directive is reported at the right file.

  • mat:autoclass option :access-list-members: (MATLAB access lists: Access = ?Cls or {?A, ?B}) replaces :friend-members:, which is still accepted. Class names may be given with or without ?.

  • Fixed member selection of mat:autoclass and mat:autofolder:

    • At the project root, members without help were listed without :undoc-members:.

    • Access = 'private' (quoted) counted as public.

    • :members: a, b on a class warned “missing attribute” and documented nothing.

    • Enumeration values were missing from “Enumeration Values”.

    • autoclass_content = "both" or "init" added “The type of the None singleton.” to a class without a constructor.

    • With matlab_auto_link, a line without a name (such as ---) after “See also” crashed the build.

    • mat:autofolder with :members: listed files in the file system’s order, which differs between operating systems; they are sorted by name.

  • Help text and warnings follow MATLAB R2026a more closely: a lone CR ends a line; after ... at the end of the superclasses, a comment on the continued line is not help (the next block is); an arguments entry ending with ; takes the comment after it, like a property. A parse failure names the innermost syntax error, or no line when tree-sitter cannot locate it.

  • New warnings: mat.invalid_matlab for a .m file with NUL bytes (likely binary), and mat.parse_error for a folder whose entries cannot be accessed (listed but not entered).

  • A function file of an @ folder whose class file was removed is a function again in the next build; it stayed a method. Cached environments from earlier versions are rebuilt.

  • A function’s or method’s help could be a later comment block before its first statement (a copyright line, a developer note), not always the same one from build to build. Nested functions no longer add their outputs, arguments and help to the enclosing function. Name-value arguments take the help of the last one every time. Cached environments from earlier versions are rebuilt.

  • Fixed matlab_auto_link: a link next to a character that cannot border inline markup (y=f(1)) broke the reST (“start-string without end-string” warnings); names between | bars (MATLAB’s code markup) or next to / are no longer linked; links and “Bases:” entries resolved in the primary domain, so they did not link without primary_domain = "mat".

  • Help of only blank % lines crashed the build.

  • An old-style property without a default (p@double vector) lost its type and size.

  • New builder matlab-api-check (sphinx-build -b matlab-api-check): checks the help text of every indexed function, class, public method, script and app (the H1 line; inputs, outputs and name-value sections, or arguments-block comments), logs each finding as mat.api_check, writes api-check.txt and api-check.json, and exits with status 1 when a rule with severity error finds something. New configuration: matlab_api_check_rules, matlab_api_check_enabled and matlab_api_check_ignore_patterns. Cached environments from earlier versions are rebuilt.

  • matlab-api-check has three new rules that warn by default: example and method-example (the help of a function, class, script or method, except a constructor, has an example section: Example:, Examples, Usage:, .. rubric:: Examples, …) and property-description (every public property has a comment). Reports count properties (property). Cached environments from earlier versions are rebuilt.

  • New configuration matlab_api_check_files (default None, every file) and matlab_api_check_files_from (a text file of entries, one per line): matlab-api-check checks only the files whose path references match the entries (paths or glob patterns relative to the project root; folder/ for the files below a folder; a comma-separated string from -D), for example the files a change touches. The index, the pages and the links are those of the whole project; files that are not selected are not parsed for the check. An empty selection checks nothing. An entry that selects no file is logged as an error and makes the exit status 1, unless the new matlab_api_check_ignore_unmatched is True. The reports count the files not selected (not_selected) and, in api-check.json, describe the selection (selection); without a selection they are unchanged.

  • New configuration matlab_api_check_section_labels: the labels that the inputs, outputs, name-value and example sections of matlab-api-check accept, replacing the built-in ones for the sections it names ("<built-in>" adds them back).

  • Breaking: the auto directives accept only the options that do something. mat:autofolder no longer accepts :inherited-members:, :special-members:, :imported-members:, :ignore-module-all: and :no-value:; mat:autodata no longer accepts :annotation: and :no-value:; no auto directive accepts :no-index-entry:. They were inherited from Python’s autodoc and ignored. mat:autofolder accepts :protected-members:, :hidden-members: and :access-list-members:, which apply to the classes it documents. Every directive that takes :noindex: also takes :no-index:.

  • Breaking: the unused module sphinxcontrib.mat_lexer (a Pygments lexer, used by the parser before tree-sitter) is removed.

  • The package metadata names the license in LICENSE, BSD-2-Clause (it said BSD-3-Clause).

  • Sidecar docs: tutorials and notes as .md and .rst files among the MATLAB files, selected by the new matlab_src_sidecar_suffixes (default [], off) and the include and exclusion patterns. The new directive mat:autosidecar renders one into a document, with relative images, downloads, includes and Markdown links (to sidecar docs, code and files) resolved from its folder; the new role :mat:sidecar: links to one. sphinx-matlab-apidoc -c writes a page for each (guide.md -> guide-md.rst, new template sidecar.rst.jinja), lists them on their folder’s page and uses a folder’s README as its introduction (new template keys sidecars and readme). matlab-api-check has the new rules sidecar-documented and sidecar-links, and counts sidecar docs (sidecar) in its reports. Markdown needs the new markdown extra (myst-parser). New warning subtype mat.sidecar. Cached environments from earlier versions are rebuilt.

  • Breaking: relative paths in help text are relative to the folder of the code file, as in sidecar docs: images, figures, downloads, literalinclude, include, and hyperlinks (to a sidecar doc, a code file’s API entry, or a download). They were relative to the documentation page. Links with a URI scheme (an e-mail address, matlab:) are left as they are.

  • New configuration matlab_external_names: regular expressions of names the project does not document. A mat reference to such a name that resolves to nothing is text, without a “reference target not found” warning. The default covers MATLAB’s own classes and namespaces (handle, matlab.*, Simulink.*, double, datetime, containers.Map, …), so “Bases: handle” no longer needs a nitpick_ignore.

  • New command sphinx-matlab-quickstart (also python -m sphinxcontrib.matlab_quickstart): sets up Sphinx documentation for a MATLAB project. It asks one question per choice, with defaults read from the project (the MATLAB release in its CI files and README, git submodules, the MATLAB project path, uv, Markdown notes next to the code, a survey of the help headings for napoleon_custom_sections), and writes conf.py, index.rst, Makefile, make.bat, a build guide and the API pages. In a uv project it adds the docs dependencies with uv add --frozen --group docs, the matlabdomain requirement copied from how matlabdomain is installed; it adds lines to .gitignore and .gitattributes, and stops if one of these files has uncommitted changes. -n writes nothing and prints what it would write; --answers FILE reads saved answers; -q asks nothing. It prints a report: the inventory, the help headings, the copyright blocks that run into help, and the next steps.

0.22.1 (2024-08-17)¶

  • Fixed Issue 262. The API for sphinx.environment.BuildEnvironment.doc2path was changed to return a path-like object in Sphinx 8.0.2.

0.22.0 (2024-07-17)¶

  • Fixed Issue 249. Parsing of multiline property default values.

  • Fixed Issue 252. Added missing class and method attributes.

  • Fixed Issue 243. Fixed issue with autolinking when the short name matches a module name.

  • Fixed Issue 250. Removed unused and undocumented MatInstanceAttributeDocumentor, which hindered Napoleon to apply styling to inline on property comments.

  • Added new configuration: matlab_show_property_specs. When set to True it will print the property specification for class properties.

0.21.5 (2024-02-10)¶

  • Fixed Issue 240, where links in literal blocks where not detected correctly.

0.21.4 (2024-01-04)¶

  • Fixed issue with warning if there is a mismatch between filename and classname, if the classname is a reserved word (like arguments).

  • Fixed a problem with PR 230 introduced in solving Issue 204: when more than one (sub)directory in the project had the same name, a dict was added to entities_table that broke autolinking (see also Issue 235).

0.21.3 (2024-01-02)¶

  • Fix issue with parsing of MATLAB files, where keywords were used in struct fieldnames. E.g. a = pkg.arguments. These were mistaken as keyword tokens and could result in warnings with Check if valid MATLAB code..

  • Bump copyright to 2024.

0.21.2 (2023-12-17)¶

  • Interpret matlab_src_dir relative to the Sphinx source directory to be compatible with sphinx-multiversion.

0.21.1 (2023-12-16)¶

  • Fixed Issue 204, that caused an AttributeError to be thrown if a module was named the same as the short name for a class.

0.21.0 (2023-12-16)¶

  • Allow matlab_src_dir to be a relative path of the conf.py file. See PR 224 and PR 225.

  • Fixed Issue 220. Parsing of property docstring could throw warning if there were blank lines between comments.

  • Fixed Issue 221. Using builtin’s in class folder definition for methods defined in other files, threw a parsing warning.

  • Fixed Issue 225. Empty @classfolder would throw an assertion error.

0.20.2 (2023-09-15)¶

  • Fixed Issue 214 again. Any folder below a @classfolder must be ignored.

0.20.1 (2023-09-14)¶

  • Fixed Issue 214. After fixing Issue 56, we introduced a bug parsing private folders incorrectly.

0.20.0 (2023-09-13)¶

  • Fixed Issue 188 and Issue 189, which caused the extension to crash if the documentation contained :exclude-members:.

  • Added a new configuration: matlab_auto_links. It will automatically convert the names of known entities (e.g. classes, functions, properties, methods) to links! This means that we can write class documentation as MATLAB Class Help suggests. Including property and methods lists in the class docstring.

  • Fixed Issue 56. MATLAB Folder Class definitions, i.e. prefixed with @, are now treated as normal classes. All methods defined in the class definition and in files in the @-folder are available. Further, it can referenced by a shortened name. Before you had to explicitly write out the “module”, class and methods. Now you can just write the class name. Only caveat is that Issue 44 still applies.

0.19.1 (2023-05-17)¶

  • Fix parsing of classes with trailing ; after end

  • Fix bug if extension is included, but matlab_src_dir is not set.

0.19.0 (2023-05-16)¶

  • Added new configuration: matlab_short_links. Finally, we are getting closer to render documentation closer to how MathWorks does it. The parsing of MATLAB functions, clasess, etc. was rewritten. We now parse all MATLAB files in matlab_src_dir. Further, you can now generate docs for files in the root folder (something that only worked for packages before).

  • We also updated the class rendering to be closer to that of MathWorks. Instead of putting both properties and methods together, they are now grouped by: Constructor Summary, Property Summary and Method Summary.

0.18.0 (2023-04-14)¶

  • Improved rendering of class property default values when matlab_show_property_default_value = True. Multiline default values are now truncated to one line. Excessive spacing is removed and values are just shown verbatim as they were parsed instead of in string.

0.17.1 (2023-04-12)¶

  • Fix issue with incorrect parsing of baseclasses with trailing comments. Reported in Issue 172.

0.17.0 (2023-03-24)¶

  • Replace directive.warn (deprecated) with logger.warning. Reported in Issue 166.

  • Fix property validation parsing reported in Issue 167.

  • Updated Author to Jørgen Cederberg as agreed in Issue 164.

0.16.0 (2023-03-15)¶

  • Add new option, matlab_show_property_default_value. Default is now to not show property values. If a property value is None, is not shown anymore.

0.15.2 (2023-03-14)¶

  • Fix issue with not parsing property docstrings correctly with Pygments 2.13. Issue 152.

0.15.1 (2023-02-06)¶

  • Fix being unable to document methods with name get. Issue 151.

0.15.0 (2023-01-02)¶

  • Pygments >= 2.14.0 is now supported. Pygments tokenization changed to return Token.Text.WhiteSpace for newline characters. This resulted in a infinite loop when parsing MATLAB files.

0.14.1 (2022-09-02)¶

  • Fix parsing of overloaded class parameters with validation functions. Issue 145.

  • Fix link in readme file.

0.14.0 (2022-06-01)¶

  • Sphinx >= 5.0.0 is now supported. Fixed errors due to deprecated Sphinx API.

  • Fixed https://github.com/sphinx-contrib/matlabdomain/issues/134. JupyterBook complains if a domain doesn’t support resolve_any_ref.

0.13.0 (2022-02-13)¶

  • Explicit set parallel_read_safe to False to avoid error in parallel builds.

  • Fixed Issue 125. Finally, we are able to support long docstrings for properties. It works as the same as MATLAB. Comment lines above a property are now treated as docstrings.

0.12.0 (2021-06-12)¶

  • Only Sphinx >= 4.0.0 is now supported.

  • Only Python >= 3.6 is supported.

  • Fixed numerous warnings due to deprecated Sphinx API. * Use sphinx.ext.autodoc.directive.DocumenterBridge.record_dependencies instead of sphinx.ext.autodoc.directive.DocumenterBridge.filename_set. * Use str.rpartition() instead of sphinx.util.rpartition() * Remove use of sphinx.util.force_decode(). * Use inspect.getmembers() instead of sphinx.util.inspect.safe_getmembers(). * Remove use of encoding argument in autodoc.Documenter.get_doc().

  • Fixed Issue 101.

  • CI now tests on Python 3.6, 3.7, 3.8 and 3.9.

0.11.8 (2021-05-12)¶

  • Limit to Sphinx < 4.0.0, due to too many breaking changes.

  • Last version to support Python 2.7

0.11.7 (2021-02-24)¶

  • Fixed Issue 117. Parsing errors due to “…”. Fix MatObject::_remove_line_continuations to take MATLAB strings into account.

0.11.6 (2021-02-23)¶

  • Fixed Issue 116. Failure on parfor statements in class methods. Fix MatFunction class to also take parfor into account when counting end.

0.11.5 (2021-01-05)¶

  • Fixed Issue 114. NoneType AttributeError in import_object. It was caused by a bug when parsing method names with trailing spaces.

0.11.4 (2020-11-30)¶

  • Remove import of six.

0.11.3 (2020-10-10)¶

  • Fixed Issue 108. Quote is not recognized as transpose after a closing curly brace.

  • Fixed Issue 109. Sphinx 3.1.1 changed API causing tests to fail.

  • Fixed Issue 111. fnable Function Arguments Support.

0.11.2 (2020-05-18)¶

  • Fixed Issue 103. If a double quoted string was followed by a single quoted string, the lexer would produce incorrect token, causing the a parser warning. Fixed by merging parts from pygments.

0.11.1 (2020-01-07)¶

  • Fixed bug when Python and MATLAB sources are in the same base folder. Reported by Alec Weiss. Historically we stored parsed MATLAB objects in sys.modules. However, this conflicts with Python modules.

0.11.0 (2019-10-29)¶

  • Fixed Issue 93. If a package class inherited from another package class, the link to the base class was incorrect. This is fixed now.

  • Merged PR #96, which adds the option matlab_keep_package_prefix. Setting this option, strips the + from package names. This gives far better rendering of documentation, as now closer resembles the actual usage for the end user.

  • Merged PR #97, which adds support for documenting MATLAB application files with a new directive application. They are referenced with app

0.10.0 (2019-10-23)¶

  • Fixed Issue 63. Finally, documents can have Python and MATLAB sources auto-documented together. Before, the MATLAB autodoc directives shadowed the Python directives, making it impossible for them to co-exist. The MATLAB modules now have their own module index generated.

0.9.0 (2019-05-29)¶

  • Merge PR #92 Fix autodoc parsing error when source matlab file is not encoded as UTF-8. This adds the option matlab_src_encoding, where one can define a different source file encoding. Default is to use utf-8, where unknown characters are replaced with �. This fixes a long time issue with the parser failing with non utf-8 files.

0.8.0 (2019-05-11)¶

  • Fixed Issue 91. Static methods in folder based classes.

  • Replaced Pygments MATLAB lexer with own. Removes issues with functions being incorrectly parsed, handles double quoted string correctly.

0.7.1 (2019-04-03)¶

  • Fixed Issue 90. Wrong function name parsed when method escapes first argument with ~.

0.7.0 (2019-03-29)¶

  • Support for Sphinx >=2.0.0. Fixes Issue 89.

0.6.0 (2019-03-29)¶

0.5.0 (2019-02-02)¶

  • Fixed Issue 84. Undocumented members are always included regardless of :undoc-members:.

  • Fixed Issue 85. Matlab parsing “seems” to hang if code contains a bunch of “%” consecutively. Thanks to GulyasGergelyR for reporting and providing a much better solution.

  • Fixed Issue 86. Handles the DeprecationWarning: `formatargspec` is deprecated since Python 3.5. Use `signature` and the `Signature` object directly.

  • Fixed Issue 87. Strings in double quotes are not parsed correctly by pygments.

  • Closed Issue 82. Instead of renaming getter and setter functions to get_whatever, they are not documented anymore. This is in line with MATLAB documentation https://se.mathworks.com/help/matlab/matlab_oop/property-access-methods.html, as these functions cannot be called directly.
